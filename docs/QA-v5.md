## 测试与回归

- `node --test`：35 项全部通过（14 冒险 + 16 旧解谜 + 5 地牢）。改动断言：第 0 间教学房 `['fly','fly','fly']`；自动战斗全流程在新密度下照常通关（每房 180 秒上限充裕）。
- 模块导入版本统一升至 `?v=5`（adventure / scene / adventure-ui / index.html / 两个测试文件），避免线上缓存混用旧模块实例导致 `WORLD` 活绑定分叉。
- 商店 E2E 期间发现的两个测试方法学坑（非游戏 bug）：①后台标签页 rAF 冻结，需聚焦且桌面窗口可见；②页面卸载时游戏自身的 `pagehide` checkpoint 会覆盖测试构造的存档，需后注册同名监听写回，且 `location.reload()` 与后续 evaluate 存在竞态——本轮用「已暂停旧标签页写档 + 新标签页读取」绕开。

## 兼容性

- 存档 key 仍为 `sunlit-ruins-v3`（v3.x 系列内互读）：已清房间、钥匙、购买与强化全部保留；敌群密度变化只影响未进入房间的生成细节，不影响进度。
- 旧版推箱谜题（puzzle.html / app.js / levels.js）与 courier.svg 原样保留，未做任何改动。

## 遗留观察

- 桌面浏览器窗口不可见时画布不渲染（rAF 节流），恢复可见即正常；与玩法无关。
- 本轮未调怪物属性数值（HP/攻击随层数成长曲线沿用 v3.1.0），只加密度。若试玩后觉得后期偏难，下一步可微调 `[3,4,4,5,5,6]` 或守卫随从阈值。

## v3.2.1 增补 · 主角换用以撒本体精灵

用户对 Canvas 手绘小旅行家的反馈是「太丑」，指定改用《以撒的结合》本体人物形象，与四张怪物贴图风格统一。

- **素材**：`characters/costumes/character_001_isaac.png`（512×512，32×32 帧网格）原样复制为 `assets/sprites/isaac.png`。头身两层按 `001.000_player.anm2` 自身的锚点叠加：身体 pivot(16,25) 偏移 +2、头部 pivot(16,28) 偏移 -5，整体 1.5 倍缩放并下移 15.5px，脚底落在 y+16（与旧主角占地一致，碰撞圈覆盖躯干与下半张脸）。
- **动画**：上下朝向共用 y=32 行 10 帧行走循环（12fps），侧面用 y=64/96 行并镜像处理右向；头部按朝向取下/侧/上帧，每 3.7 秒切一次眨眼帧；移动中朝移动方向、静止时朝瞄准方向。冲刺拖尾、无敌闪烁、出生保护半透明全部保留；贴图加载失败时回退简笔形象。
- **验证**：35 项测试全绿（scene.js 不在测试导入链上，无断言变动）；浏览器端与「按 anm2 公式手工绘制参照图」逐像素 diff，除地面砖纹与投影外完全一致；额头肤色、双眼（黑瞳+泪光高光）、身体与脚部像素采样全部命中；上下/左右/镜像四朝向渲染签名互不相同，上朝向确认无五官（后脑勺）。
- **模块版本**：`scene.js` 与 `adventure-ui.js` 升 `?v=6`（world/adventure 保持 `?v=5`，按「每个目标文件的 specifier 全局一致」原则无分叉）；toast 阈值 4→5。
- **测试方法学新坑**：页面内 `import()` 对同 URL 返回缓存的模块实例——编辑源码后必须重载页面再验，否则跑的是旧模块（本轮曾被它误导出一轮“渲染错位”的假结论）。
